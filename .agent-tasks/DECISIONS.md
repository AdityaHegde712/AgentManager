# AgentRunner Decisions

1. Use a local TypeScript web app for the embedded terminal and dashboard.
2. Implement OpenRouter only; isolate all LLM behavior behind a provider contract.
3. Read `OPENROUTER_API_KEY` only from the process environment; never persist secrets.
4. Use an approved evidence ladder: deliverable, selected handoff, selected `.agent-tasks` documents, transcript fallback, Git state.
5. Allow two coding PTYs overall and one active PTY per repository root.
6. Launch `codex resume --all` for v0.1. Defer local Codex session indexing.
7. Treat the assistant as one persistent local orchestration thread, not one assistant instance per project. Project scope is explicit per continuation request.
8. Keep v0.1 chat-shaped only: OpenRouter may draft continuation briefs but must not provide general assistant replies or implicit project-context recall.
9. Keep the embedded terminal for v0.1 behind a `TerminalSurface` contract. vNext may offer a user-triggered, tokenized browser pop-out attached to the same PTY; it must not start a second assistant or CLI session.
10. Do not expose a project selector in the chat shell. Derive the active project context from the current orchestration thread; project registration, folder scanning under `~/Projects/`, and assisted project creation are deferred features.
11. Store the current v0.1 thread's explicit workspace attachment in the `project` URL query parameter. If absent, auto-attach only when exactly one project is registered; never guess among multiple projects.
12. Authenticate normal API requests from the launch-token header and browser WebSocket upgrades from the launch-token query value. Both paths use timing-safe launch-token verification.
13. Support local dotenv ingestion only at server startup. Load `.env` with `override: false` so a deliberately exported process variable remains authoritative; never persist or log provider keys.
14. Replace the two-port Vite/backend launch with one loopback Fastify origin that serves the built UI. The bootstrap capability is printed only in a URL fragment and moved to browser session storage immediately; it is never accepted as a normal HTTP query parameter.
15. Do not put the launch capability in terminal WebSocket URLs. An authenticated terminal-start response sets a SameSite=Strict, HttpOnly cookie scoped to `/api/v1/terminals`; the WebSocket route verifies only that cookie.
16. Add a native Windows folder picker endpoint (`POST /api/v1/system/browse-folder`) executed securely via a backend script (PowerShell .NET FolderBrowserDialog), preventing manual path typos.
17. In the conversation flow, implement two-step heuristic project inference: regex/keyword match against registered project aliases. If multiple match, prompt user with explicit clarification choices. If one matches, show a confirmation card before locking for handoff.
18. Support OpenRouter free routing and models: include `openrouter/free` as a default virtual free-router option, and filter all fetched models to only those ending with `:free` (or zero-cost pricing). Expose full error diagnostic strings if provider status or model fetching fails.
19. Enforce three independent scroll containers: left thread history, center chat feed, and right request controls rail, with composer pinned at bottom (`position: sticky; bottom: 0`). Add a registered projects inspector panel showing names and roots with click-to-view details.
20. Normalize and expand tilde (`~`) paths across all backend filesystem interactions (`os.homedir()`) and project registration, supporting POSIX and Windows style roots seamlessly.
21. When a user message references a project name or path not yet registered in the catalog, extract candidates and provide an inline 1-click registration/auto-discovery card in the chat feed (e.g. `[Register 'capstone' at ~/Projects/Capstone]`) rather than requiring manual navigation to the sidebar.
22. Provide a lightweight CLI testing/debug tool (`npm run cli -- <args>`) to inspect backend health, project list, brief generation, and terminal sessions without needing browser interaction.
23. Auto-discover project evidence on backend: when drafting a brief for a resolved project, automatically check and read `HANDOFF.md`, `.agent-tasks/PLAN.md`, `.agent-tasks/DECISIONS.md`, `.agent-tasks/TASKS.md`, and execute `git status --short` in the project root. Fall back to manual context inputs only if files are absent.
24. Ephemeral progress indicator: display real-time intermediary progress states (e.g. "Scanning project context...", "Reading HANDOFF.md...", "Running git status...", "Calling OpenRouter...") in the chat feed only while in-flight; replace with final formatted response once completed.
25. Persistent project catalog and directory scanning: persist registered projects in storage (`projects.json`), support folder scanning (`POST /api/v1/projects/scan`) that auto-registers all immediate subdirectories, plus project deletion and alias editing endpoints (`DELETE /api/v1/projects/:alias`, `PATCH /api/v1/projects/:alias`).
26. Migrate Windows folder dialog to modern Windows File Explorer dialog style (`System.Windows.Forms.OpenFileDialog` with `CheckFileExists = $false; ValidateNames = $false; FileName = 'Select Folder'`), and render uncompressed full-height chat bubbles (ChatGPT-style) without internal text-area scroll compression.
27. Enforce project deduplication based on canonical root path (`path.resolve(path)`). Any attempt to add or scan an existing root path is ignored by the backend, and surfaces a temporary frontend notification in red (`#ff0f0f`) with white text ("One or more duplicates were attempted to be added and were ignored."). Existing persisted duplicates in `projects.json` are sanitized on load.
28. Emulate brief streaming in the frontend word-by-word at ~100 words per second (~10ms/word): the backend retains its robust single-pass HTTP JSON contract without stateful SSE complexity, while the frontend delivers a responsive typewriter effect into the brief card before settling into static editable state.
29. Non-persistent project confirmation: dismiss project inference and confirmation cards immediately upon user selection ("Confirm project", "Choose another"), ensuring ephemeral selection gates do not clutter ongoing chat history.
30. Visual composer spacing: provide dedicated margin and flex gap between composer input text area and the submit button / scope indicators to prevent cramped or touching UI elements.
31. Native Codex TUI Delegation: delegate session picking to Codex CLI's native `codex resume` interactive picker inside ConPTY/xterm.js instead of custom session directory crawling, allowing natural keyboard navigation and clean `Esc` fallback to a new session.
32. Context Packet Streamlining: eliminate manual file override textareas (`handoff.md`, `.agent-tasks`, `git status`) from the request controls rail, relying on backend auto-discovery, while retaining an optional transcript textarea styled to expand vertically up to `max-height: 240px` and scroll internally beyond that.
33. Scalable Project Catalog Truncation: display the first 5 projects by default with a toggle ("Show all N projects" / "Show fewer") to maintain sidebar ergonomics as workspaces scale, leaving "Register a project" and "Scan Directory" permanently visible.
34. Thread Unused Guard & Taxonomy: enforce at most one unused (0 user messages) orchestration thread at any given time. Clicking "+ New orchestration thread" re-routes to the existing unused thread if present. Provide hover-revealed rename (pencil icon) and delete actions on each thread item.
35. Dynamic Multi-Project Scoping: decouple conversation threads from static project locks. Run project inference on every composer prompt; if a different project or path is detected, prompt for project confirmation and dynamically update thread scope rather than forcing the previously active project. Continue with active project only when no project reference is detected in the input.
36. Git Bash Terminal Integration: support Git Bash (`bash.exe -l -c "<codex-command>; exec bash"`) as the primary PTY shell wrapper on Windows. Resolves Git Bash path (`C:\Program Files\Git\bin\bash.exe`, etc.) and sets POSIX environment (`SHELL`, `PATH`). If Codex exits, the PTY transitions into an interactive Git Bash session, providing POSIX shell ergonomics (`ls`, `cat`, `git`) directly in the embedded work surface. Automatically falls back to native `codex.exe` if Git Bash is not installed.
37. Project Inference Precedence & Fallback Selector: evaluate known registered catalog matches (`inferProject`) before unregistered candidate extraction (`detectUnregisteredPathOrCandidate`). Blacklist common English verbs/stop words (`needs`, `has`, `is`, `was`, `requires`, `contains`, `wants`, etc.) from phrase extraction. Provide an inline manual selection fallback ('Select registered project...') on candidate and prompt cards so users can directly pick their target workspace from the catalog in a single click.
38. Composer Workspace Selector & OpenRouter Toolcall Sanitization: Replace fragile natural language regex inference on composer deliverable prompts with an explicit workspace selector dropdown directly inside the composer (`.compose-project-picker`). Selecting a workspace immediately scopes the thread and directly drafts the continuation brief without false-positive project candidate prompts. Harden the OpenRouter continuation brief prompt to explicitly declare no tools/bash execution capability and mandate strict Markdown sections (`# Continuation Brief`, `## 1. Objective & Requested Deliverable`, `## 2. Evidence & Context Summary`, `## 3. Constraints & Operational Directives`, `## 4. Immediate Concrete Next Action`). Strip hallucinated toolcall XML tags (`<dots_function_call>`, `<invoke>`, `<function_calls>`) from responses, ensuring pure Markdown output for downstream agent handoffs.
