# AgentRunner v0.1 — Local Coding-Agent Hub

## Summary

Build a localhost TypeScript web app in ~12–16 hours that prepares and hands off Codex coding sessions. It runs one assistant control process and up to two asynchronous Codex terminal PTYs, with no concurrent sessions in the same repository root.

The assistant gathers approved evidence, creates an OpenRouter-powered continuation brief, then opens Codex’s native cross-project resume picker inside an embedded terminal. You select the session and take over; the assistant never writes concurrently to that terminal.

## Implementation changes

1. Create a Node/TypeScript backend with Fastify, WebSocket, and `node-pty`, plus a React/Vite/xterm.js UI.
   - Bind only to `127.0.0.1` and require a fresh launch token in the local URL.
   - Supervise terminal lifecycle, resize, disconnect, stop, and output buffering.
   - Launch subprocesses with executable-plus-argument arrays only; never interpolate user, session, or LLM text into shell commands.
   - Enforce two active coding sessions total and block a second session for any already-active repository root.

2. Add an OpenRouter brief connector.
   - Read `OPENROUTER_API_KEY` only from the launch environment; never persist, display, pass in command arguments, or log it.
   - Fetch the live model catalog and require a user-selected currently-free fixed model.
   - Store only non-secret local settings under the user-local application-data directory: selected model, project aliases, and UI preferences.
   - Define a routing interface with fixed-model mode active in v0.1 and an inactive future `auto` mode seam; do not implement task-complexity routing yet.

3. Implement the continuation workflow.
   - Resolve `<project_name>` from auto-discovered/owner-saved directory aliases.
   - Collect evidence in this order: requested deliverable, selected `HANDOFF.md`, selected current `.agent-tasks` state documents, selected Codex transcript only as a last resort, and displayed Git status.
   - Require an evidence-selection review and generated-brief approval before opening Codex.
   - Start `codex resume --all` in the embedded PTY for the user to choose a session. Keep the approved brief visible with a deliberate “send to terminal” action after selection.
   - Preserve Codex’s default sandbox and approval behavior; reject unsafe bypass/yolo flags.

4. Stage session discovery rather than relying on undocumented Codex storage.
   - **v0.1:** native `codex resume --all` picker plus embedded terminal takeover.
   - **v0.1.1:** read-only, version-gated metadata index with explicit user confirmation before exact `codex resume <SESSION_ID>`.
   - **v0.2 candidate:** opt-in full-text transcript search, only after parser fixtures prove compatibility and privacy behavior.

## Test plan

- Write frozen behavioral tests before implementation; do not modify them during implementation.
- Unit-test alias resolution, evidence priority, OpenRouter request normalization, free-model validation, token redaction, and same-root concurrency rejection.
- PTY integration-test terminal output/input/resize/disconnect using a harmless fake CLI.
- Test that rejected briefs cannot launch or inject prompts, the local server rejects missing/invalid tokens, and only loopback binding is allowed.
- Owner-run smoke: choose a real prior Codex session through the embedded picker, approve a brief, transfer input control, and confirm the resumed terminal remains usable.

## Assumptions

- Codex remains the sole v0.1 coding-agent adapter; Antigravity is a later adapter spike.
- The app is single-user and local-only; no LAN access, accounts, cloud deployment, or background autonomous completion.
- Native session selection is deliberate: Codex documents `resume --all` for cross-directory selection and exact session-ID resume, while its local session catalog is not a stable public automation contract. [Codex CLI reference](https://learn.chatgpt.com/docs/developer-commands?surface=cli)
- North is architectural inspiration only. Its Python/FastAPI orchestration and broader provider/job surface will not be copied into this narrow MVP. [North repository](https://github.com/Kushagrabainsla/north)
- OpenRouter remains an independent brief-generation provider; it does not control Codex sessions. [OpenRouter quickstart](https://openrouter.ai/docs/quickstart)

# AgentRunner v0.1 — Local Coding-Agent Hub

## Summary

Build a local TypeScript web app in ~12–16 hours that prepares and hands off Codex sessions. v0.1 implements OpenRouter only, while keeping the assistant-LLM backend modular for future providers.

The assistant runs separately from up to two Codex terminal sessions, never permits two coding agents in one repository root, and gives you terminal takeover through the local UI.

## Implementation changes

1. Build the local app with a Node/TypeScript backend (`Fastify`, WebSocket, `node-pty`) and React/Vite/xterm.js UI.
   - Bind only to `127.0.0.1`; require a fresh launch token in the opened URL.
   - Manage PTY lifecycle, terminal input/output, resize, stop, and disconnect.
   - Launch commands as executable-plus-argument arrays; never shell-interpolate user, session, or model output.
   - Allow two active coding sessions total; block a second session for the same repository root.

2. Define a modular assistant-LLM provider boundary.
   - Add provider contracts for `healthCheck`, `listModels`, and `createBrief`.
   - Represent provider state as `unconfigured`, `checking`, `healthy`, `degraded`, or `unavailable`.
   - Implement only the `OpenRouterProvider` adapter in v0.1.
   - Read `OPENROUTER_API_KEY` from the launch environment only. Never persist, render, log, or pass it as a command argument.
   - Keep a provider registry so future API-key providers can be added as isolated adapters without changing the brief workflow.

3. Add provider-aware UI behavior.
   - Show configured providers and their latest health result.
   - Enable the assistant-provider/model selector only for `healthy` providers.
   - In v0.1, OpenRouter exposes currently-free models; the user selects one fixed model.
   - Pin the provider and model used for each draft brief, so changing a later selection does not silently alter an already approved handoff.
   - Reserve the routing configuration shape for future fixed-model versus auto-routing modes; activate only fixed OpenRouter selection now.

4. Implement the continuation flow.
   - Resolve project aliases to roots.
   - Build evidence in priority order: requested deliverable, selected `HANDOFF.md`, selected `.agent-tasks` state documents, then selected Codex transcript if prior evidence is insufficient.
   - Show selected evidence and require approval of the generated brief.
   - Launch `codex resume --all` in the embedded PTY; you select the Codex session and can deliberately send the approved brief afterward.
   - Preserve Codex sandbox and approval defaults; reject unsafe bypass flags.

5. Stage session discovery.
   - **v0.1:** native Codex resume picker and embedded terminal takeover.
   - **v0.1.1:** read-only, version-gated session metadata index with explicit confirmation before exact session-ID resume.
   - **v0.2 candidate:** opt-in transcript search only after parser compatibility and privacy behavior are proven.
